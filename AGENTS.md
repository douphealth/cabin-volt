## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

- CabinVolt data is a static JSON registry (src/data) evaluated client-side by src/lib/logic.ts; keep verdict logic in that one engine so every page agrees.
- Store retrieval and reviewed-passage evidence separately from inherited source dates; an HTTP success or source hash must never automatically update safety rules or verification status.

## Homepage design (do not put index.html at the repo root)
An `index.html` in the repo root is picked up by Nitro as the page template for EVERY route — it
replaced sitemap.xml, /privacy and every deep page with the homepage (2026-11-23). The hand-made
homepage design lives in `design/home.html`; run `node scripts/build-home.mjs` after editing it.
That writes `src/home/home.html` (served at "/" only, by `src/home/serve.ts`), WebP images in
`public/img/` and a precompiled Tailwind file `public/home-<hash>.css`. robots.txt, sitemap.xml and
llms.txt are generated by the app — files with those names in the repo root are ignored.
